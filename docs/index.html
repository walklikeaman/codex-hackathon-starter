Агент ставит всё остальное сам

Открой Codex в папке, где хочешь держать проект, и вставь этот промт. Агент выполнит его автономно.

вставь это в Codex
Ты — мой агент настройки окружения. Выполни всё автономно и отчитайся в конце.

1. Склонируй репозиторий https://github.com/walklikeaman/codex-hackathon-starter.git и зайди в его папку.
2. Запусти ./setup.sh — поставит CodeGraph, подключит его к Codex (codegraph install) и положит скиллы /ship и /loop-* в ~/.codex/prompts.
3. Запусти ./scaffold.sh — создаст рабочее Next.js-приложение в папке ./app.
4. Убедись, что scaffold создал app/.env.local из .env.example — общие ключи Supabase уже вшиты в репозиторий, вписывать ничего не нужно.
5. Прочитай AGENTS.md, TASKS.md и TEAMWORK.md — это правила, доска задач и как мы работаем командой. Записи веди в wiki/log.md, доску обновляй в TASKS.md, быстрые заметки — в notes/.
6. Проверь: `codex mcp list` показывает codegraph; в ~/.codex/prompts лежат ship.md и loop-*.md.
7. Отчитайся коротко: что готово и что осталось за мной (вписать ключи Supabase, вход в Codex).

Важно: НЕ создавай таблицы в базе и не придумывай схему, пока не зафиксирована идея проекта — схему решаем в первые 15 минут кикоффа. Останавливайся и спрашивай только если шаг нельзя выполнить без меня. После подключения CodeGraph напомни, что Codex надо перезапустить.
→клонирует общий репозиторий команды
→ставит CodeGraph и подключает его к Codex
→кладёт скиллы /ship, /loop-demo, /loop-lint и остальные
→создаёт рабочее приложение и проверяет установку
↻После того как агент подключит CodeGraph, перезапусти Codex (закрой и открой заново) — тогда он загрузится.
3

Доступ и общие ключи

База и деплой — общие, их держит команда. Ключи Supabase уже вшиты в репозиторий — scaffold сам заполняет app/.env.local, вписывать ничего не надо. Свои Supabase и Vercel не заводи.

Деплой сам: пушишь ветку в общий репозиторий, и общий Vercel собирает превью-ссылку. Локально ничего настраивать не нужно.

Доступ на запись: скинь свой GitHub-ник владельцу — добавят в Collaborators, и /ship сможет пушить.

Готово — можно строить

Открой репозиторий в Codex, заполни блок «Проект» в AGENTS.md (что строим, стек, один демо-путь) и опиши задачу словами. Дальше — /loop-demo до зелёного и /ship, чтобы сохранить.

?codex: command not found после установки
Глобальная папка npm не в PATH этой сессии. Открой новый терминал; если не помогло — добавь $(npm prefix -g)/bin в PATH. И не путай: пакет называется @openai/codex, а не codex.
?./setup.sh упал на установке
Чаще всего это Node ниже 22 или права на глобальный npm. Поставь Node 22 через nvm (nvm install 22) — тогда sudo не нужен — и запусти ./setup.sh снова, он идемпотентный.
?Агент не может создать таблицу в Supabase
Схему ведёт один человек — тот, кто запускал ./setup.sh --infra. У него MCP Supabase должен пройти браузерный вход и выбрать общий проект («покажи проекты Supabase» откроет вход). Остальные читают базу через общие ключи в app/.env.local, отдельный доступ не нужен.
?codex mcp list не показывает codegraph
Запусти ./setup.sh ещё раз в папке репозитория и перезапусти Codex. Вручную: codegraph install и выбери Codex CLI. Supabase и Vercel MCP нужны только тому, кто ведёт бэкенд — он ставит их через ./setup.sh --infra.

Как работаем командой

Роли раздаём на кикоффе, а правила — заранее. Главное: разные ветки, сводит в одну один человек.

→каждый в своей ветке feature/…, в main мёржит только интегратор (через Pull Request)
→на кикоффе фиксируем скоуп и контракт данных — тогда бэкенд и фронт идут параллельно
→интеграция каждые 60–90 минут: все пушат, интегратор сводит в main, деплой превью
→/ship часто, маленькими коммитами; доску задач ведём в TASKS.md
📋Полные правила — TEAMWORK.md, доска задач (её Codex читает на старте) — TASKS.md. Роли впишете туда на кикоффе.
Репозиторий: github.com/walklikeaman/codex-hackathon-starter. Подробности установки — INSTALL.md, как устроено окружение — docs/agent-framework.md. Вопросы по настройке — в чат команды.
