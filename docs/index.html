5

Как работаем командой

Главное правило: разные ветки → один сводит в main. Так четверо не толкаются.

  • Каждый — в своей ветке (feature/<коротко>). Пушишь → открываешь PR → интегратор мёржит в main.
  • В main пушит только интегратор. Общий Vercel собирает превью на каждую ветку.

Роли (разбираем на кикоффе, ~1 человек на каждую)

  • Интегратор / main — держит main зелёным, мёржит PR, ведёт скоуп.
  • Бэкенд — Supabase: схема (/schema), API. Схему ведёт он один.
  • Фронтенд — экраны и флоу.
  • Демо и деплой — гоняет демо-путь целиком, /ui-polish, запись демо, /pitch.

Кикофф (первые 30–45 минут, все вместе)

  • Выбрать идею (раздел ниже), заполнить блок «Проект» в AGENTS.md: идея, стек, один демо-путь, что вне скоупа.
  • Договориться о контракте данных (таблицы/поля) — тогда бэк и фронт идут параллельно.
  • Нарезать демо-путь на 4–6 кусков, вписать в TASKS.md, разобрать по себе.

Ритм: git pull перед стартом · /ship часто · интеграция каждые 60–90 минут (все пушат, интегратор сводит, деплой превью, проверяем что демо-путь жив).

Идеи проекта

6 идей под категории, все собираются вчетвером за 7 часов, с сильным живым демо. Выбираем одну на кикоффе, её промт вставляем в блок «Проект» в AGENTS.md — дальше /autopilot → /loop-demo → /ship.

★ Apps for your life · фаворит

SnapSell — фото вещи → готовое объявление

Демо: наводишь камеру на любую вещь (хоть рюкзак из зала) → через 5 сек карточка «$40–55, потому что…» → Post → влетает в живую ленту.
Почему: вау из вещи в руках человека, поток линейный, почти нечему ломаться, результат — красивый шареабельный артефакт.
▸ промт для Codex 
Проект: SnapSell — «сфоткал вещь → готовое объявление». Стек: Next.js (App Router) + Supabase (таблица listings) + Vercel, GPT-vision через OpenAI API на сервере. ОДИН демо-путь: экран с кнопкой камеры → фото → vision возвращает строгий JSON {title, description, condition, category, price_range, reasoning} → рендерим красивую карточку объявления → кнопка Post пишет в Supabase и показывает в общей ленте. Вне скоупа: auth, оплата, редактирование, реальная eBay-интеграция. Первый шаг: подними Next.js, заведи таблицу listings и роут /api/analyze, который принимает base64-фото и возвращает захардкоженный JSON — потом подключи модель.

Codex Colosseum — 3 агента на один баг

Демо: вводим баг → три колонки, live-диффы + авто-тесты → у двоих зелёный чек → «Merge winner».
Почему: прямо в тему OpenAI Build Week; eval-харнесс для промптов, боль каждого разработчика.
▸ промт для Codex 
Проект: Codex Colosseum — арена из 3 агентов на один баг. Стек: Next.js + Supabase (таблица runs) + Vercel, 3 параллельных вызова OpenAI на сервере. ОДИН демо-путь: захардкоженный файл с падающим тестом → кнопка Run → 3 вызова с разными системными промптами стримят диффы в 3 колонки → гоним фиксированный тест-набор в serverless → pass/fail-бейдж → Merge winner кладёт выбранный дифф в результат. Вне скоупа: git-push, авторизация, история, произвольные репо, больше одного файла. Первый шаг: свёрстай 3-колоночный экран со стрим-плейсхолдерами и заготовь мини-репо (файл + красный тест) как фикстуру.

Почему: живой голос бьёт зал сильнее текста; фишка — перебивание и адаптивность на лету.

Первый шаг: подними Realtime-соединение в браузере с примитивным систем-промптом «экзаменуй по этому тексту, перебивай на ошибке», проверь двусторонний звук, потом привяжи загруженный PDF как контекст.

How we work as a team

The key rule: separate branches → one person merges into main. That's how four people don't collide.

  • Everyone works on their own branch (feature/<short>). Push → open a PR → the integrator merges into main.
  • Only the integrator pushes to main. The shared Vercel builds a preview for every branch.

Roles (claim at kickoff, ~1 person each)

  • Integrator / main — keeps main green, merges PRs, guards the scope.
  • Backend — Supabase: schema (/schema), API. One person owns the schema.
  • Frontend — screens and flows.
  • Demo & deploy — runs the whole demo path, /ui-polish, records the demo, /pitch.

Kickoff (first 30–45 minutes, together)

  • Pick an idea (below), fill the "Project" block in AGENTS.md: idea, stack, the one demo path, what's out of scope.
  • Agree on the data contract (tables/fields) — then backend and frontend go in parallel.
  • Slice the demo path into 4–6 pieces, put them in TASKS.md, claim them.

Rhythm: git pull before you start · /ship often · integrate every 60–90 minutes (everyone pushes, the integrator merges, deploy a preview, check the demo path still works).
